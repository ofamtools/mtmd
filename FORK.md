# FORK.md: mtmd, the tuios daemon for embedding

`ofam.dev/mtmd` is a fork of [Gaurav-Gosain/tuios](https://github.com/Gaurav-Gosain/tuios)
that keeps only tuios's daemon and the packages the daemon needs, so a host
program (mtm) can link the daemon into its own binary and need no `tuios` on
PATH. It shares git history with upstream, so `git merge vX.Y.Z` keeps working.

It is local to the o-family and is not published. `upstream` is the remote for
github.com/Gaurav-Gosain/tuios. `~/proj/tuios` (remote `local-tuios`) is the
owner's own checkout of it and is never touched from here.

### The rewrite (`scripts/ofam-rewrite.go`)

Rewrites `github.com/Gaurav-Gosain/tuios` to `ofam.dev/mtmd` in `go.mod`, in Go
import specs, and in the Go files of its `pathStrings` table. It leaves URLs,
git remotes and docs alone, and leaves the gob type name
`github.com/Gaurav-Gosain/tuios/internal/session.TerminalState`
(`internal/session/codec.go`, `snapshot_pack_test.go`): it is written into saved
state and the wire format, so renaming it would make saved terminal state
unreadable and break compatibility with an unforked tuios of the same protocol.
`-check` exits 1 while a module-path reference is left. Idempotent.

### The facade (`serve`)

`serve.Main(args []string, opt serve.Options) int`. `args` are the words after
the host's own. It is in a package of its own, not the root package, so upstream
adding a root file never conflicts with it. It runs:

| Command line | What |
|---|---|
| `[--server NAME] daemon [--log-level L] [--no-restore] [--adopt-fd=N]` | the daemon in the foreground; `--adopt-fd` is the live upgrade's second image |
| `[--server NAME] start-server` | spawn a detached daemon, return when one answers |
| `daemon handoff-accepts` | the live-upgrade preflight |
| `agent-proto --protocol acp\|codex [--harness H] [--cwd D] -- AGENT...` | the pane program of a protocol agent (cobra-free port of upstream's `agent_proto_command.go`) |
| `__plugin-reaper PROGRAM...` | the reaper that herdr plugin commands run under |

`Options.SelfCommand` is the prefix by which the host runs itself again,
`{"", "mtmd"}` for `mtm mtmd ...`; nil is upstream's behaviour. `Options.Version`
is the label the daemon reports in `hello`. Not exposed, by the owner's
decision: the rest of tuios's command line, and mail.

Self re-exec goes through `internal/selfcmd` (`Exe`, `Argv`, `Words`). The sites
that run it: `internal/session/agent_protocol.go` (protocol panes),
`handoff.go` (the live-upgrade exec), `handoff_preflight.go` and
`handoff_prev.go` (`daemon handoff-accepts`), and `serve` (start-server and the
plugin reaper). Left on `os.Executable()` on purpose: `handoff_prev.go`'s copy of
the running binary, `herdrcli/run.go`, `release/installed.go`.

### The prune (`scripts/ofam-prune.go`)

Keep rule, in this order:

1. Roots: `./serve`. Kept packages are its dependencies in this module, for
   linux, darwin and windows, plus the test dependencies of every kept package,
   to a fixed point (`-list` prints them).
2. A file is kept when the nearest directory at or above it that holds Go files
   is a kept package: that keeps `testdata`, embedded files and the LICENSE /
   NOTICE / COPYING files that sit with kept code.
3. Root files by name: `LICENSE`, `NOTICE`, `README.md`, `FORK.md`,
   `THIRD_PARTY.md`, `go.mod`, `go.sum`, `.gitignore`, `.gitattributes`;
   `scripts/ofam-*.go`; `third_party/`.
4. Everything else goes: the terminal interface, `cmd/`, docs, e2e, every nested
   module (`vt`, `sketch`, ...: `go.mod` pins them at the published versions,
   identical to the in-tree copies, and the build fetches them), `go.work`.
5. `third_party/tuios.dev/MODULE/` is written from the pinned module's LICENSE,
   NOTICE, COPYING and OFL files, so the notices of linked upstream code stay
   in the tree.

`go run scripts/ofam-prune.go -check` lists what it would delete or write and
exits 1 if there is anything. `-tidy` also runs `go mod tidy` (not part of the
recipe: it would make `go.mod` conflict at every merge).

## Merging the next upstream tag

The order matters: the rewrite comes before the prune, because `ofam-prune` asks
`go list` which packages the facade needs, and merged upstream lines still carry
the old module path until the rewrite has run.

```sh
cd ~/proj/mtmd
git fetch upstream --tags
git worktree add .worktrees/sync-vX.Y.Z -b sync-vX.Y.Z <fork integration branch>
cd .worktrees/sync-vX.Y.Z
export GOWORK=off GOFLAGS=-trimpath GOMAXPROCS=4
git -c merge.directoryRenames=false merge vX.Y.Z   # will stop with conflicts
git checkout --ours README.md                       # ours: the credit README
go run scripts/ofam-rewrite.go                      # new upstream lines carry the old path
go run scripts/ofam-prune.go                        # deletes every modify/delete and new pruned file
go run scripts/ofam-rewrite.go -check && go run scripts/ofam-prune.go -check
go build ./... && go vet ./serve ./internal/selfcmd
nice -n 20 go test -p 2 ./serve ./internal/selfcmd ./internal/session/...
git add -A && git commit                            # the merge commit
```

`merge.directoryRenames=false` matters: the prune moved `sketch/LICENSE` and
friends to `third_party/tuios.dev/sketch/`, and with directory-rename detection
git puts new upstream files of `sketch/` there as conflicts. With it off, the
conflicts are exactly: `README.md` (take ours) and one modify/delete per upstream
change to a pruned file, all resolved by the prune script. `go.mod` and `go.sum`
merge on their own; upstream's pins win, and the rewrite fixes the module path.
If a hand-edited file of patch 2 (`internal/session/...`) conflicts, keep
`selfcmd.Argv` / `selfcmd.Exe`.

Proof (lane `mtmd-1b-prune`): the commits of this fork were applied to
`v0.12.0` and `v0.12.1` was merged with the commands above: 64 modify/delete
conflicts and one content conflict (`README.md`); after the steps the tree was
byte-identical to the fork built directly on `v0.12.1`.

After the merge:

1. `grep -rn 'os.Executable' --include='*.go' internal serve | grep -v _test`:
   read every hit that is not in the list above. A new self-exec must use
   `selfcmd.Argv`.
2. Read the upstream release notes for a new daemon verb that spawns
   something, and for anything that changes `cmd/tuios`'s `daemon`,
   `start-server`, `agent-proto` or `handoffArgs` (their bodies are mirrored in
   `serve`, because the files they live in are pruned): port the change.
3. Optional: `go mod tidy` (or `go run scripts/ofam-prune.go -tidy`) drops the
   requirements that only pruned code used (78 to 52 lines of `go.mod`
   requirements at v0.12.1). It is not part of the recipe because it makes
   `go.mod` conflict at the next merge. Without it, a host's `go.mod` gets one
   more bump (`golang.org/x/net`).
4. Run the matomeru contract suite against a wrapper binary built from `serve`
   (`internal/daemon/contract/README.md` in matomeru; `Options{}`, the file
   named `tuios-vX.Y.Z`).
5. Update this file: the upstream tag, and any new patch.
