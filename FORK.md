# FORK.md: mtmd, the tuios daemon for embedding

`ofam.dev/mtmd` is a fork of [Gaurav-Gosain/tuios](https://github.com/Gaurav-Gosain/tuios)
that keeps only tuios's daemon and the packages the daemon needs, so a host
program (mtm) can link the daemon into its own binary and need no `tuios` on
PATH. It shares git history with upstream, so merging an upstream tag (`git merge upstream-tags/vX.Y.Z`) keeps working.

It is local to the o-family and is not published. `upstream` is the remote for
github.com/Gaurav-Gosain/tuios. `~/proj/tuios` (remote `local-tuios`) is the
owner's own checkout of it and is never touched from here.

### The rewrite (`scripts/ofam-rewrite.go`)

Rewrites `github.com/Gaurav-Gosain/tuios` to `ofam.dev/mtmd` in `go.mod`, in Go
import specs, and in the Go files of its `pathStrings` table. It leaves URLs,
git remotes and docs alone, and leaves the gob type name
`github.com/Gaurav-Gosain/tuios/internal/session.TerminalState`
(`internal/session/codec.go`, `snapshot_pack_test.go`): it is written into saved
state and the wire format, so renaming it would make saved terminal state
unreadable and break compatibility with an unforked tuios of the same protocol.
`-check` exits 1 while a module-path reference is left. Idempotent.

### The in-tree emulator (`scripts/ofam-vt.go`)

`internal/vt` (with `internal/vt/snapshot` and `internal/vt/vtgen`) is a copy of
the `tuios.dev/vt` module at the version in `scripts/vt-version`, plus
`scripts/vt-ofam.patch` (the evict hook, below). It is generated
and committed; `internal/vt/{LICENSE,NOTICE,README.md}` are the module's own.
The script copies everything but `go.mod`/`go.sum`, moves the module's
self-imports to `ofam.dev/mtmd/internal/vt...`, and applies the patch with
`patch -p1` inside the tree. It rebuilds the tree from scratch (never edit
`internal/vt` by hand: change the patch). `-check` exits 1 when the committed
tree differs. `go.mod` no longer requires `tuios.dev/vt`; its own dependencies
(`ultraviolet`, `x/ansi`, `libghostty`, `progstatus`) were already required.

`scripts/ofam-rewrite.go` has a `movedImports` table (`tuios.dev/vt` ->
`ofam.dev/mtmd/internal/vt`) that moves import lines of the old path, so upstream
code merged back in that still imports `tuios.dev/vt` is fixed by the same run;
`-check` lists any left.

- At an upstream merge: `git merge upstream-tags/vX`, then `ofam-rewrite`
  (it also fixes new `tuios.dev/vt` imports), `ofam-prune`, then `ofam-vt -check`
  (upstream never touches `internal/vt`, so it stays clean). If upstream's
  `go.mod` brings back a `tuios.dev/vt` line, delete it.
- The evict hook (`vt-ofam.patch`): `Scrollback.SetOnEvict(fn func(EncodedRow))`
  is called, in order and once per line, just before a push overwrites the
  oldest line of a full ring and for each line `SetMaxLines` drops when it
  shrinks (not for `Clear`, `Discard` or a reflow's take-back of the newest
  lines). `EncodedRow.Data` is the stored encoding, valid during the call, with
  interned colours rewritten as RGB. Nil by default: one nil check per push (a
  flood benchmark shows no difference between nil and a no-op hook). The
  libghostty backend has no hook. The daemon installs it in every pane (patch
  #8). A hook may wait (a shrink hands it a whole ring and the daemon's hook
  waits on the log's queue rather than dropping), the emulator is stalled
  meanwhile. When `SetMaxLines` shrinks it copies the kept lines into one
  array, each capped, so the pages of the dropped lines can be freed whole
  (lane M7: measured, it is most of what a demotion gives back).
- At a vt version bump: write the new version in `scripts/vt-version`, run
  `GOWORK=off go run scripts/ofam-vt.go`, then ofam-rewrite and ofam-prune, fix
  `vt-ofam.patch` if it fails to apply, run `go test ./internal/vt/...
  ./internal/session/... ./serve`.
- `tuios.dev/vt` is still linked by programs that import it themselves (the mtm
  client through ochazuke); those are separate Go packages from `internal/vt`.

### The cold scrollback log (`internal/coldlog`)

New mtmd-only package, not an upstream patch and not generated: the on-disk,
compressed, append-only log of scrollback rows that the vt evict hook (patch
#7) feeds. It imports `internal/vt` (for `EncodedRow` and the row decoders) and
`internal/atomicfile`, and nothing from tuios, so an upstream merge never
touches it. An idle log frees its queue arrays and gzip state. Writer goroutine with a bounded queue and gap markers, 256-row
gzip blocks with CRC, write-once segments with a footer, torn-tail recovery,
random-access reader (`Log.AppendWait` for a producer that would rather wait than drop), per-log and total retention, `closed.json` orphan
markers with a grace-period purge, flock-based sole-writer lock. Lane M3 wires
it into the daemon (patch #8 below); user documentation: README.md, "Scrollback on disk"; plan: `o-plans/plans/mtmd-scrollback-disk.md`.

### Host names (`internal/hostnames`, patch 13)

The names of the daemon's socket folder and file, its state folders and its
configuration folder are one table, `hostnames.Names`, in data. `Upstream` is
tuios's and the default; a host passes its own as `serve.Options.Names`
(`serve.Names`, an alias), which `serve.Main` installs before anything
resolves a path. Every upstream file that builds one of those paths reads the
table through a one-line call (the files are listed in row 13), so an upstream
change to those files conflicts on one line at most. After a merge,
`grep -rn '"tuios.sock"\|"tuios/\|"tuios-servers"\|tuios-%d' --include='*.go' internal serve | grep -v _test`
lists any new hard-coded name to route through the table.

| Field | Upstream | mtm (`matomeru/internal/daemon` Layouts row `mtm`) |
|---|---|---|
| `SocketApp` (under `$XDG_RUNTIME_DIR`, `/run/user/UID`, `%LOCALAPPDATA%`) | `tuios` | `mtm` |
| `SocketTmp` (`/tmp/<SocketTmp><uid>` without a runtime folder) | `tuios-` | `mtm-` |
| `SocketFile` | `tuios.sock` | `mtm.sock` |
| `StateApp` (default server, under the state home) | `tuios` | `mtm` |
| `StateServers` (one state home per named server) | `tuios-servers` | `mtm/servers` |
| `ServerApp` (a named server's folder in its state home) | `tuios` | (the state home itself) |
| `ConfigApp` (under the config home) | `tuios` | `mtm` |

On macOS a named server's state moves from `~/Library/Application Support/tuios-servers/NAME/tuios/`
to `~/Library/Application Support/mtm/servers/NAME/`, its socket from
`/tmp/tuios-UID/servers/NAME/tuios.sock` to `/tmp/mtm-UID/servers/NAME/mtm.sock`
(not `$TMPDIR`: macOS's per-user temp folder is about 50 bytes long and the
agent-link sockets beside the daemon's would pass the 104-byte limit), and the
configuration from `.../tuios/config.toml` to `.../mtm/config.toml`. The data
folder (worktrees, herdr plugin locks, cloned repos) and the harness folder keep
upstream's `tuios` names.

`Names.Env` are variables exported beside upstream's: `{Name: "MTM_SOCKET",
Upstream: "TUIOS_SOCKET"}`. `hostnames.Mirror` sets them in every child the
daemon starts with an environment of its own (`ptyspawn.SpawnTTY`, the single
door of every pane; hook commands; plugin processes): it drops inherited
assignments of the host's names and adds each with the value of the last
assignment of its upstream one. `hostnames.ApplyEnv`, at the top of
`serve.Main`, gives every upstream variable the value of its host name when that
is set, so upstream code reads the host's name first without a change.
`serverscope.Apply` sets and clears both names.

`Names.DropUpstream` (default false: both names, as before) removes the upstream
name of every `Env` pair from those children, so a pane carries only `MTM_*`
for the paired variables. `hostnames.MTMEnv` (public as `serve.MTMEnv`) is the complete table for the
`MTM_` prefix (every `TUIOS_` variable the daemon sets for a pane, hook command
or plugin process, or reads from a process's or its own environment: the pane
identity, token, grants, tty, host, restored marker, the hook context, the plugin
id and token, and the daemon's tunables); a host passes it as `Names.Env` with
`DropUpstream` and no `TUIOS_` variable reaches a child. A variable the daemon
starts to set or read gets its pair there. Left out, and listed in the table's
comment: `TUIOS_AGENT` (a user's hint, read as `MTM_AGENT` first), the e2e/test/legacy
switches, `TUIOS_HANDOFF_FALLBACK` (a marker between two daemon images),
`TUIOS_SOUND_PATH` (the Windows sound player's own script), and the tuios
binary's own variables. `TUIOS_INTEGRATION_ID` / `_VERSION` / `TUIOS_SKILL_SUM`
are text markers inside installed files, not variables. The daemon reads a pane process's variables through
`hostnames.Lookup` (host name first, then upstream: `procinfo.EnvironVar`,
`checkSocketEnv`), `herdrplugin.cleanEnv` and `guestenv` also strip the host's
names, so pane identification, hook origin and nested attach work either way.

The one-time move (`serve/migrate.go`): `daemon` (not `--adopt-fd`) and
`start-server` first move a named server's state from the upstream folder to
the host's when the host's is absent and upstream's exists (a rename: same
volume), write `MOVED-TO` beside the folder it left and `MOVED-FROM` inside the
moved one, and copy the configuration file when the host has none (the old one
stays). A daemon answering on the upstream socket (or a live pid in its pid
file) refuses the move and the start, changing nothing. The default (unnamed)
server is not moved: its state shares a folder with the configuration.
`[--server NAME] migrate-paths [--dry-run] [--rollback]` runs the same move on
its own and prints a JSON report; `--rollback` renames back (refused while a
daemon answers on the host's socket) and removes the markers; the copied
configuration file stays.

### The facade (`serve`)

`serve.Main(args []string, opt serve.Options) int`. `args` are the words after
the host's own. It is in a package of its own, not the root package, so upstream
adding a root file never conflicts with it. It runs:

| Command line | What |
|---|---|
| `[--server NAME] daemon [--log-level L] [--no-restore] [--adopt-fd=N]` | the daemon in the foreground; `--adopt-fd` is the live upgrade's second image |
| `[--server NAME] start-server` | spawn a detached daemon, return when one answers |
| `[--server NAME] migrate-paths [--dry-run] [--rollback]` | the one-time move of the server's state to the host's names (patch 13), as a JSON report |
| `daemon handoff-accepts` | the live-upgrade preflight |
| `agent-proto --protocol acp\|codex [--harness H] [--cwd D] -- AGENT...` | the pane program of a protocol agent (cobra-free port of upstream's `agent_proto_command.go`) |
| `__plugin-reaper PROGRAM...` | the reaper that herdr plugin commands run under |

`Options.SelfCommand` is the prefix by which the host runs itself again,
`{"", "mtmd"}` for `mtm mtmd ...`; nil is upstream's behaviour. `Options.Version`
is the label the daemon reports in `hello`. `Options.Names` is the host's
table of folder, socket and variable names (patch 13); nil is upstream's. Not exposed, by the owner's
decision: the rest of tuios's command line, and mail.

Self re-exec goes through `internal/selfcmd` (`Exe`, `Argv`, `Words`). The sites
that run it: `internal/session/agent_protocol.go` (protocol panes),
`handoff.go` (the live-upgrade exec), `handoff_preflight.go` and
`handoff_prev.go` (`daemon handoff-accepts`), and `serve` (start-server and the
plugin reaper). Left on `os.Executable()` on purpose: `handoff_prev.go`'s copy of
the running binary, `herdrcli/run.go`, `release/installed.go`.

### The prune (`scripts/ofam-prune.go`)

Keep rule, in this order:

1. Root: `./serve`. Kept packages are its dependencies in this module (`internal/coldlog` among them since lane M3 links it from the daemon), for
   linux, darwin and windows, plus the test dependencies of every kept package,
   to a fixed point (`-list` prints them).
2. A file is kept when the nearest directory at or above it that holds Go files
   is a kept package: that keeps `testdata`, embedded files and the LICENSE /
   NOTICE / COPYING files that sit with kept code.
3. Root files by name: `LICENSE`, `NOTICE`, `README.md`, `FORK.md`, `CHANGELOG.md`,
   `THIRD_PARTY.md`, `go.mod`, `go.sum`, `.gitignore`, `.gitattributes`;
   `scripts/ofam-*.go`, `scripts/vt-version`, `scripts/vt-ofam.patch`; `third_party/`.
4. Everything else goes: the terminal interface, `cmd/`, docs, e2e, every nested
   module (`sketch`, ...; `vt` is regenerated in tree by `ofam-vt.go`: `go.mod` pins them at the published versions,
   identical to the in-tree copies, and the build fetches them), `go.work`.
5. `third_party/tuios.dev/MODULE/` is written from the pinned module's LICENSE,
   NOTICE, COPYING and OFL files, so the notices of linked upstream code stay
   in the tree.

`go run scripts/ofam-prune.go -check` lists what it would delete or write and
exits 1 if there is anything. `-tidy` also runs `go mod tidy` (not part of the
recipe: it would make `go.mod` conflict at every merge).

## Versions and tags

mtmd has its own versions: its tags are `vX.Y.Z` of mtmd, not of tuios
(`v0.1.0` is upstream `v0.12.1`, pruned). Each release records the upstream
tag it is based on in the tag message.

Upstream's tags (`v0.1.0` to `v0.12.1`, and later) collide with those names, so
they live in `refs/upstream-tags/`, not `refs/tags/`. Never push upstream tags
to `origin`: push only `git push origin main` and `git push origin vX.Y.Z`.

On a fresh clone, recreate the remote configuration:

```sh
git remote add upstream https://github.com/Gaurav-Gosain/tuios.git
git config remote.upstream.tagOpt --no-tags
git config --add remote.upstream.fetch '+refs/tags/*:refs/upstream-tags/*'
git fetch upstream
```

## Merging the next upstream tag

The order matters: the rewrite comes before the prune, because `ofam-prune` asks
`go list` which packages the facade needs, and merged upstream lines still carry
the old module path until the rewrite has run.

```sh
cd ~/proj/mtmd
git fetch upstream   # no --tags: the remote's refspec brings tags into refs/upstream-tags/
git worktree add .worktrees/sync-vX.Y.Z -b sync-vX.Y.Z <fork integration branch>
cd .worktrees/sync-vX.Y.Z
export GOWORK=off GOFLAGS=-trimpath GOMAXPROCS=4
git -c merge.directoryRenames=false merge upstream-tags/vX.Y.Z   # will stop with conflicts
git checkout --ours README.md                       # ours: the credit README
go run scripts/ofam-rewrite.go                      # new upstream lines carry the old path
go run scripts/ofam-prune.go                        # deletes every modify/delete and new pruned file
go run scripts/ofam-rewrite.go -check && go run scripts/ofam-prune.go -check
go build ./... && go vet ./serve ./internal/selfcmd
nice -n 20 go test -p 2 ./serve ./internal/selfcmd ./internal/session/...
git add -A && git commit                            # the merge commit
```

`merge.directoryRenames=false` matters: the prune moved `sketch/LICENSE` and
friends to `third_party/tuios.dev/sketch/`, and with directory-rename detection
git puts new upstream files of `sketch/` there as conflicts. With it off, the
conflicts are exactly: `README.md` (take ours) and one modify/delete per upstream
change to a pruned file, all resolved by the prune script. `go.mod` and `go.sum`
merge on their own; upstream's pins win, and the rewrite fixes the module path.
